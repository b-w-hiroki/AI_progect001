# ADR 0001: アーキテクチャ決定を記録する

- ステータス: 承認
- 日付: YYYY-MM-DD

## 背景

設計判断の「なぜ」はコードに残らない。数週間後には本人も忘れる。
AIに実装させる場合はこの問題が増幅される — セッションをまたぐと文脈が消えるため、
一度決めたことを次のセッションで蒸し返したり、逆の判断をしたりする。

## 決定

設計上の判断をしたら、`docs/adr/` に1ファイル追加する。

- ファイル名: `NNNN-短い説明.md`（連番）
- 内容: 背景 / 決定 / 結果 の3節
- 決定を覆すときは既存ファイルを書き換えず、**新しいADRを追加して古い方を「非推奨」にする**

## 結果

- 「なぜこうなっているか」の問い合わせが減る
- AIに `docs/adr/` を読ませることで、決定済みの議論を繰り返さなくなる
- 書く手間が増える。1件5分以内で書ける粒度に留め、些細な判断は記録しない
