# ADR 0002: 検証コマンドを `make check` 1つに集約する

- ステータス: 承認
- 日付: YYYY-MM-DD

## 背景

AIは「コマンドを実行 → エラー出力を読む → 修正する」というループで精度を上げる。
このループの質は、検証コマンドの以下の性質に強く依存する。

- **単一であること** — 何を実行すべきか迷わない
- **速いこと** — 遅いと実行回数が減り、まとめて修正して失敗しやすくなる
- **出力が機械可読であること** — ファイル名・行番号・エラーコードが出る

言語ごとにコマンドがバラバラだと、AIは毎回どれを実行するか推測することになる。

## 決定

`make check` を唯一の入口とし、lint・型チェック・テストをすべて実行する。
CI もローカルと**同じコマンド**を呼ぶ（`make setup && make check`）。

型チェックは strict を維持する（mypy strict / tsconfig strict）。
型エラーは人手のレビューを介さずAIに届く検証信号なので、緩めると効果が失われる。

## 結果

- `CLAUDE.md` に書く指示が1行で済む
- 「ローカルでは通るがCIで落ちる」が構造的に起きにくい
- ツールを増やすたびに `make check` が遅くなる。1回の実行が数十秒を超えたら、
  高速な単一バイナリ（ruff / biome）への置き換えや、並列化を検討する
